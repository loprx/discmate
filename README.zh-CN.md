# DiscMate

[English](README.md) · **简体中文**

DiscMate 是 Apple Silicon Mac 上的免费光盘刻录工具。你可以把文件和文件夹刻到空白 DVD+R，也可以往仍有可写空间的多会话 DVD+R 里追加文件。追加时，旧文件继续使用盘上的原有数据，只需写入新增内容和新的目录。

## 我的光盘能追加吗？

**已在数据 DVD+R 上完成实盘追加并重新装盘读回的有 3 种目录布局**。下表按已有光盘的文件系统统计。照片、ZIP、文档等都可以作为普通文件写入。

| 已有 DVD+R 的目录布局 | 可以追加什么 | 验证范围 |
| --- | --- | --- |
| ISO 9660 + Joliet | 普通文件和文件夹，含中文、多层目录和空目录。单个新增文件及新会话镜像均须小于 4 GiB | 多轮实盘追加、读回哈希匹配，旧文件区段保持 |
| ISO / UDF 1.02 混合盘 | 根目录普通文件，新旧合计最多 32 个。新增文件须非空且小于 1 GiB，UDF 根目录须能放入一个扇区 | 实盘重新装载后，从两套目录核对了新旧文件、文件名和哈希 |
| 纯 UDF 1.02，单物理分区 | 普通文件和目录。旧文件须各占一个连续区段，新增文件须非空且小于 1 GiB | 在已有 89 个文件的盘上追加一张照片，重新装盘后 90 个文件的哈希逐个匹配 |

**实盘追加未验收**

- **UDF 2.01（VAT 虚拟分区）**：在一张 DVD+R 上读出过原有的 5 个文件。新增文件只写进过离线测试镜像。尚未验证实际写盘、收尾推出，以及重新装盘后新旧文件的数据完整性。
- **仅有 ISO 9660 主目录**：已从离线多会话镜像提取文件并核对哈希，实盘追加和重新装盘读回尚待验证。

CD、其他 DVD 盘型和蓝光尚未完成同等追加验证。盘片还须允许追加，并有足够空间。在「查看刻录摘要」时，DiscMate 会检查当前盘片的会话、目录和可写空间。

## 刻录、追加与读回

1. **添加文件。** 在「数据光盘」中选取文件或文件夹，也可以从访达拖入或按 ⌘V 粘贴。粘贴纯文本会生成 TXT 文件，最多 1 MiB。
2. **查看刻录摘要。** 首次写入空白盘时，保留默认勾选的「保留后续追加能力（多会话）」，方便下次加文件。已有数据盘只需添加本次的新内容，标准追加仅读取旧目录和区段信息。同路径目录可以合并，已有文件不能覆盖。
3. **确认并开始刻录。** 「刻录后由系统校验」默认关闭，可按需勾选。在写入和收尾期间保持光驱连接及供电。若收尾状态不明，使用「重新检查设备」确认盘片状态。
4. **打开或校验内容。** 重新装盘后，若访达显示的是旧会话，可在应用中选择「在访达打开最新内容」并授权只读挂载。「读回校验」可只读本次新增文件，也可完整读取；有源清单的文件可以核对 SHA-256。大盘日常追加无需重读全部旧文件。

## 其他功能

- **音频、镜像和视频。** 可制作音频 CD、刻录光盘镜像或已有的 VIDEO_TS 文件夹。另有可擦写光盘擦除和光盘信息查看入口。
- **未完成的 DVD+R 会话。** 对可识别的未关闭会话，可手动关闭；符合条件的空白预留轨道可以续写。关闭预留轨道会占用整条轨道的空间，确认前可在摘要中查看。
- **速率与诊断。** 可选择刻录速率，在主窗口查看数据刻录阶段和耗时。发生异常时，可按任务预览并导出脱敏诊断，查看设备状态、USB 错误和收尾记录。

## 安装与更新

需要 Apple Silicon Mac、macOS 13 或更新版本，以及与盘片匹配的刻录机。

```sh
brew install --cask loprx/tap/discmate
```

更新已安装的应用：

```sh
brew update
brew upgrade --cask loprx/tap/discmate
```

也可在「DiscMate → 设置 → 软件更新」检查更新。手动下载的 ZIP 使用 ad hoc 签名，尚未经 Apple 公证；首次打开如遇系统提示，可按单应用放行步骤操作。[下载安装包与校验值](https://github.com/loprx/discmate/releases) · [Apple 首次打开说明](https://support.apple.com/102445)

## 从源码构建

安装 Xcode Command Line Tools 后运行以下命令。测试在本地镜像上执行，构建产物位于 `build/DiscMate.app`。

```sh
zsh test.sh
zsh test.sh --large-iso  # 可选，1.12 GB 离线回归
zsh build.sh
```

## 提交改动与发布

每项功能或修复从公开仓库的 `main` 建分支并提交 PR。PR 标题会出现在发布说明中，请写清用户能观察到的变化。修复使用 `bug` 标签，功能改进使用 `enhancement` 或 `accessibility`，文档使用 `documentation`。其余 PR 归入「其他更新」。

合并待发布的 PR 后，在公开 `main` 的发布提交上推送正式版本 tag（如 `v0.5.2`）。GitHub Actions 会测试、构建并发布安装包，按已合并 PR 自动生成分类说明，再更新 Homebrew cask。
